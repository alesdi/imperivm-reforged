# `point::Rot`: the rotation scripts turn vectors with

**Status:** read from `gbr.exe` (0x00697d90); reproduced exactly in
`engine/core/src/sim/world_host.cpp` (`rotate_like_gbr`), with the table
generated by `tools/gen_rot_table.py`. This is a runtime behaviour, not a
file; nothing here is code from the executable (`docs/legal.md`).

`p.Rot(d)` turns the point `p` in place by a whole number of degrees `d`.
It has 385 shipped call sites (formations, flanking offsets, the fan of
probes a unit tests round an obstacle), and its rounding decides which cell
a unit steps to, so an approximation shows up as a unit standing one pixel
off from where the original puts it.

## What it computes

With `a` the angle in radians:

    x' = trunc(x * cos(a) + y * sin(a))
    y' = trunc(y * cos(a) - x * sin(a))

This is the transpose of the textbook anticlockwise matrix, so `Rot(90)`
sends `(x, y)` towards `(y, -x)`. Both results are truncated toward zero
by the MSVC helper `_ftol2` (0x00763870).

## How the FPU gets there

The routine is x87 code. The steps, each with its own rounding:

1. **The angle.** `d` is loaded as an integer and multiplied by the double
   at 0x007ac490, which is 0x1.1df46a2506b91p-6 = 0.017453292519444445:
   the double nearest `3.1415926535 / 180`, with pi cut at eleven digits,
   and slightly less than `pi / 180`. The game never changes the FPU's
   precision control (no code in it writes the control word, and it does
   not load Direct3D, which would), so the process runs at the Windows
   default of 53 bits: the product is rounded to a 53-bit significand,
   nearest-even.
2. **Sine and cosine.** The FPU's own sine and cosine of that angle.
   Precision control does not apply to them, so each result keeps the
   x87's full 64-bit significand.
3. **The products.** Each coordinate, an integer, is multiplied by the
   64-bit sine or cosine, and each product is rounded to 53 bits.
4. **The sums.** The two products are added (for `x'`) or subtracted (for
   `y'`), and the result is rounded to 53 bits.
5. **The truncation** toward zero. A value outside the 32-bit range gives
   the integer indefinite, 0x80000000.

Two consequences scripts see:

* `Rot(90)` is not exact. `sin(90 K)` rounds to exactly 1 at 64 bits, but
  `cos(90 K)` is 4.4896592e-11. A coordinate times it survives the 53-bit
  sum when the other term is small, so its sign decides the truncation:
  `(3, 4).Rot(270)` is `(-4, 2)`, not `(-4, 3)`.
* `Rot(30)` of `(0, 2)` is `(0, 1)`, because `sin(30 K)` is just under one
  half. `Rot(360)` is not a no-op either: `sin(360 K)` is -1.8e-10, which
  moves `(12345, -6789)` to `(12345, -6788)`.

## The engine's reproduction

The simulation uses no floating point, so the steps are done on integers.

* `tools/gen_rot_table.py` computes, offline and in exact rational
  arithmetic, the angle of step 1 and the 64-bit sine and cosine of
  step 2 for every `d` from 0 to 360. Each value is stored as a sign, a
  64-bit significand and a binary exponent in
  `engine/core/src/sim/rot_table.inc`, which is checked in.
* `rotate_like_gbr` does steps 3 to 5 exactly: each product as a 128-bit
  integer rounded to 53 bits nearest-even, the sum aligned exactly and
  rounded again, then the truncation.
* A negative `d` uses the row for `-d` with the sine negated, which is what
  the FPU's sine and cosine give: they are odd and even exactly.

## What differs, and why

* **The table assumes a correctly rounded sine and cosine.** The x87
  reduces its argument with a 66-bit approximation of pi, which moves the
  results near 180 and 360 degrees by about 1e-20. No truncation this
  routine makes can see that: the products are of integers under 2^31, and
  each sum is rounded to 53 bits first.
* **Beyond a full turn** the engine reduces `d` to within one turn; the
  original hands the raw product to the FPU. No shipped site passes a value
  outside -30 to 360.
* A sum whose two terms are more than 72 binary places apart is taken as
  the larger term. The smaller term is then under a quarter of the larger
  one's last bit and cannot change the rounding.
